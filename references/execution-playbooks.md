# 执行手册（execution-playbooks）——执行助手专用

适用：`EXECUTE`。先读本卡 + 引用的决策/契约，再按卡的领域选下面的手册（跨领域就合并几份清单）。
铁律：只跑**定向测试**（T1），不跑门禁、阶段体检、全量回归；不改契约源、迁移目录（除非卡面允许）、他人所有权路径；同卡失败 2 次就停手上报。

## 0. 编码前自评（Pre-flight self-assessment，必做，写进执行日志）

1. 先查已有记录：`node <skill>/scripts/pd.mjs ask-check . "关键词 关键词"`（检索决策登记册和任务卡；命中 DECIDED 时退出码 5）。已 `DECIDED` 的照做，**不再上报**；工具不能跑脚本时手工检索决策索引 + 任务卡 + 契约。
2. 按五个维度给出置信度 高/中/低，每项附一句依据：

| 维度 | 高 = | 低 = |
|---|---|---|
| 需求清晰度 | 目标、验收可判定 | 验收含“合理/友好/尽量” |
| 决策覆盖 | 涉及的取舍都有 DEC | 要自己选方案/默认值 |
| 契约完整度 | 字段、错误码、权限都写死 | 缺字段/错误码/角色 |
| 依赖状态 | 前置卡 DONE 且代码里真实存在 | 只有自述、未合并、迁移号未到 |
| 测试路径 | 卡面有可复制命令且本地能跑 | 无测试入口/环境缺失 |

3. **一次性**列出所有缺口/疑点/异常（文档与代码不符、前置缺失、卡面矛盾），每条标 `BLOCKING / NON_BLOCKING / UNKNOWN`；不要挤牙膏式分多轮问。
4. 任一 `BLOCKING` → **不写代码**，`pd.mjs record --event BLOCKED`，按裁决链上报规划者（缺什么决定、已查记录、证据、可选项 A/B、推荐）。
5. `NON_BLOCKING` → 写假设 + 依据 + 回退条件到执行日志，继续。全部为“高/中”且无 BLOCKING → 给 3–6 行执行计划后开工。

## 1. 通用收尾（每张卡都一样）

```text
[ ] 定向测试通过（真实运行，保存输出）
[ ] 只暂存本卡文件；git fetch && git rebase origin/<主线>；一卡一提交，信息含任务 ID
[ ] 推送 task/<ID>（或 config 规定的分支），禁止 --force
[ ] 同步检查：git fetch 后 `git rev-parse HEAD` == `git rev-parse origin/<分支>`，工作区干净
[ ] pd.mjs record：TEST_RUN → COMMITTED(--commit) → PUSHED → DONE；核验写入成功
[ ] 证据三层：E1 卡/DEC/契约编号 → E2 提交号+改动文件 → E3 测试命令+结果（不适用写 N/A+理由）
```
选定向测试：卡面 `tests.targeted` 优先；否则改动文件的同名/就近测试 + 直接调用方的测试；新逻辑没有测试就先补测试。

可选外部 Skill（装了就用，没装照本手册）：superpowers `test-driven-development`（先写失败测试）、`systematic-debugging`（测试失败时）、收尾 `code-simplifier`。

## 2. 后端 / API

**读**：API 契约（路径/方法/Schema/分页/幂等/鉴权）、Errors 契约、Identity 契约、相关 DEC、现有路由/中间件/校验库/错误处理器的实现位置。
**步骤**
1. 从契约唯一源生成或引用类型，不手抄字段。
2. 入口校验（Schema 校验在 handler 之前），未知字段按契约处理（拒绝或丢弃）。
3. 鉴权 → 授权（资源归属、角色）→ 业务 → 统一错误体。
4. 写操作按契约实现幂等键（同键同载荷返回同结果，同键异载荷报冲突码）。
5. 分页：契约规定的游标/页码、默认与上限、稳定排序键。
6. 日志：请求 ID、用户 ID、错误码；不记密码/Token/完整个人信息。
**不变量 / 常见失败**：返回码与错误码映射不符；越权（改 ID 读他人数据）；管理端接口对普通用户开放；分页重复/漏项（排序不稳定）；500 泄露栈；幂等只在内存里。
**定向测试**：本接口的请求级测试——成功、每个校验失败、未登录 401、越权 403、不存在 404、幂等重放、分页边界（首页/末页/超上限）。
**完成证据**：E1 契约接口名 + DEC；E2 提交；E3 上述用例输出。
**上报 BLOCKING**：契约缺字段/错误码/权限规则；需要改契约源；需求要的行为与契约冲突。

## 3. 业务逻辑 / 规则

**读**：规则相关 DEC（取整、币种、优先级）、规则表/状态机定义、现有领域模块与调用方。
**步骤**
1. 规则写成纯函数（输入 → 输出，无 IO、无当前时间直取，时间/随机作参数注入）。
2. 多条件规则用规则表（数据驱动），不写嵌套 if 森林。
3. 金额用整数最小单位或十进制库；取整方式与时机按 DEC，只在约定位置取整一次。
4. 状态机：显式列出状态与合法迁移，非法迁移返回明确错误；终态不可再迁移。
5. 并发：写入用乐观锁（版本号）或数据库约束/事务，不靠先读后写。
**不变量 / 常见失败**：浮点误差；多次取整；边界用错 `<`/`<=`；时区/跨日；规则优先级不明；并发下超卖/重复扣减。
**定向测试**：表驱动单测——每条规则一行、每个边界值的两侧（等于、差 1 个最小单位）、零/负/最大值、取整半数情形、全部合法与非法状态迁移；有并发要求加一个并发冲突用例。
**完成证据**：E3 附用例表与结果；规则表与 DEC 一一对应。
**上报 BLOCKING**：取整/优先级/边界归属未决定；规则互相矛盾；需求要求的状态迁移不在定义里。

## 4. 数据设计与迁移

**读**：Data 契约（实体、字段类型/可空/默认/约束、索引、软删除）、**迁移版本号顺序**、现有 schema 与最新迁移号、ORM 配置。
**步骤**
1. 确认本卡分到的迁移号 = 当前最新 + 1 且与卡面一致；不一致 → 停。
2. 表结构严格照数据契约：可空性、默认值、唯一/外键约束、索引（按查询路径，不多建）。
3. 迁移只前进、串行；已合并的迁移不修改，改动另开新迁移。
4. 加非空列：先可空 + 回填 → 再加约束（大表分批回填）。
5. 软删除：`deleted_at` 等按契约，唯一索引和查询默认排除已删除行。
6. 在执行日志写回滚说明（如何撤销、是否丢数据）；种子/fixtures 只用于测试与开发环境。
**不变量 / 常见失败**：迁移号冲突；改旧迁移；非空列无默认导致线上失败；缺索引或索引与查询不符；软删除绕过唯一约束；fixtures 混入生产数据。
**定向测试**：在空库跑全部迁移到最新；在含样例数据的库跑本迁移（含回填）；约束违反用例（唯一/非空/外键）；本卡 repository 层查询测试。
**完成证据**：E2 迁移文件名+号；E3 迁移输出 + 约束测试结果 + 回滚说明位置。
**上报 BLOCKING**：契约缺字段定义；需要不可逆数据处理（删列、改类型丢精度）；迁移号被他人占用。

## 5. 交互 / UX 逻辑

**读**：UX States 契约（空/加载/错误/无权限/成功）、Errors 契约的前端展示方式、表单校验规则 DEC、现有状态管理与请求层。
**步骤**
1. 为每个界面列出 5 态并逐一实现，错误态按错误码映射文案与操作（重试/返回/登录）。
2. 表单：前端校验与后端规则一致（同源 Schema 优先）；提交中禁用重复提交；后端错误回填到字段。
3. 乐观更新：只用于可撤销操作，失败回滚并提示；否则等待服务端结果。
4. 无障碍：可键盘操作、焦点顺序与可见焦点、表单 label、错误可被读屏读到、颜色不是唯一信号。
5. 文案走 i18n 键，不硬编码；数字/日期/货币按区域格式化。
**不变量 / 常见失败**：只做成功态；加载态闪烁或永不结束；重复提交；乐观更新失败不回滚；无权限显示成空列表；硬编码文案。
**定向测试**：组件/交互测试覆盖 5 态 + 校验失败 + 提交失败回滚 + 键盘可达；mock 请求层而非真实后端。
**上报 BLOCKING**：契约没定义某状态的行为；错误码无对应展示方式；校验规则前后端冲突。

## 6. 前端 UI

**读**：设计规范/设计 token、现有组件库与同类页面、UX States 契约、卡面视觉验收标准。
**步骤**
1. 先找可复用组件，复用 > 扩展 > 新建；新建组件放约定目录并说明为何不能复用。
2. 颜色/间距/字号/圆角只用 token，不写魔法值。
3. 响应式断点按规范；长文本、空数据、极端数量不溢出。
4. 视觉检查：本地启动截图（关键断点各一张）对照设计，截图路径记入证据。
**执行者测试范围**：只跑本卡组件/页面的定向测试；**tsc 与 build 属于阶段体检，由测试助手在阶段收口时跑**，执行者不把它当每卡门禁（卡面明确要求的除外）。
**不变量 / 常见失败**：复制粘贴旧组件造分叉；绕过 token；只在一个宽度下看；可点击区域过小；对比度不足。
**可选 Skill**：`frontend-design`、`ui-ux-pro-max`、`web-design-guidelines`。
**上报 BLOCKING**：设计与 UX 契约冲突；需要改公共组件（属于他人所有权）；缺设计且验收要求视觉一致。

## 7. 集成 / 异步事件 / 外部服务

**读**：Events 契约（事件名、载荷、触发时机、幂等键）、外部服务的接口文档与限额、超时/重试 DEC、现有适配层。
**步骤**
1. 外部调用只经适配器（接口 + 实现），业务代码依赖接口。
2. 每次调用设超时；重试只对可重试错误，指数退避 + 上限；非幂等操作不盲目重试。
3. 消费事件按幂等键去重；处理失败进死信/重试队列并记录。
4. 发布事件在业务提交之后（或用 outbox），载荷照契约。
5. 密钥从环境/密钥管理读取，永不写入代码、日志、测试数据。
**不变量 / 常见失败**：无超时挂死；重试风暴；重复消费导致重复副作用；事件在事务回滚后仍发出；测试打到真实外部服务。
**定向测试**：用 fake/stub 适配器——成功、超时、可重试错误后成功、不可重试错误、重复事件只生效一次、载荷 Schema 校验；不在定向测试里调用真实外部服务。
**上报 BLOCKING**：契约未定义幂等键或重试语义；需要新外部账号/付费资源；外部接口实际行为与文档不符。

## 8. 性能 / 探索卡

**读**：卡面的指标定义、**继续条件与停止条件**、基线（若有）、测量脚本/环境说明。
**步骤**
1. **先测基线**：固定环境、数据量、预热，重复 ≥ 3 次取中位数，记录命令与原始输出；没有基线不做优化。
2. 用剖析数据定位瓶颈，写下“预期瓶颈 vs 实测瓶颈”。
3. 一次只改一处，改后同条件复测。
4. 每轮对照卡面条件：达到目标 → 收尾；触发停止条件（无改善、瓶颈不在预期处、需改契约/架构）→ 停。
**不变量 / 常见失败**：没基线就优化；环境不同比较；单次测量下结论；为提速牺牲正确性；编造数字。
**定向测试**：本卡测量脚本 + 被改模块的功能测试（证明行为没变）。
**完成证据**：E3 = 基线与改后数字对比表、测量命令、样本次数；探索卡即使“无改善”也算有效产出，记录结论。
**上报 BLOCKING**：实测推翻卡面假设；需要改架构/契约/数据模型才能继续；指标或目标缺失。

## 9. 何时立刻停手（任何领域）
- 自评中有 BLOCKING；需要越出允许路径或改契约源。
- 同卡验收连续失败 2 次（熔断）。
- 前置任务“DONE”但代码中不存在；迁移号/文件所有权冲突。
- 推送认证失败（停止并报告，不索要令牌）。
停手动作：`pd.mjs record --event BLOCKED --note "<缺什么、证据、可选项>"`，保持工作区干净（未完成改动不提交到主线），报告后结束本卡。
