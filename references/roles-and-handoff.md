# 角色、裁决链与交接

## 角色边界
- **规划者**：全局规划、规划更新、裁决、维护决策登记册和任务索引结构、细化任务卡、生成下一批提示词。不做日常编码。
- **执行助手**：实现 + 定向测试 + 本卡提交 + 本卡留痕。只改本卡状态和本卡日志，不改别人的卡和全局结构。
- **测试助手**：门禁、阶段体检、集成验证、最终回归、独立验收、测试台账。只报告缺陷，不改被测业务代码。
- **用户**：产品方向、需求范围、重大取舍、风险接受。

一个模型可以在不同会话里担任不同角色，但同一会话开头要声明角色。

## 裁决链
1. 提问方先查：决策登记册 → 任务卡 → 契约 → 执行日志/测试台账。查到 `DECIDED` 就照做。
2. 查不到：上报规划者，附「缺什么决定、已查记录、代码/需求证据、可选项与影响、推荐项」。
3. 规划者在授权范围内裁决（实现方案、任务拆分、验收细化、非产品性的技术选择），写入决策登记册 `decided_by: planner`。
4. 只有以下情况交用户：产品行为/需求范围变化、权限与安全边界、数据不可逆处理、公共契约语义、成本/外部资源承诺、规划者与已有用户决策冲突。
5. 用户裁决写入 `decided_by: user`。用户可推翻规划者裁决，反之不行。

## 规划者的主动职责（不等人叫）
- 每个阶段体检结束：读测试助手报告，更新受影响任务（修复卡、阈值、依赖），`plan_version` 递增。
- 收到 BLOCKING 上报：当轮裁决或转交用户，不让执行方空等。
- 发现实测推翻假设（如性能瓶颈不在预期位置）：按卡面停止条件取消或替换任务，记录证据。
- 定期 `pd.mjs health`、`pd.mjs status`，把不一致修掉。

## 交接物
- 执行 → 测试：任务卡 DONE + 提交号 + 定向测试命令与结果 + 执行日志。
- 测试 → 规划者：阶段体检报告（PASS/FAIL/UNKNOWN 逐条）+ 测试台账条目 + 缺陷清单。
- 规划者 → 执行/测试：由 `pd.mjs next/prompt` 生成的启动提示词（来自权威任务卡）。
