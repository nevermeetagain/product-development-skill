# 证据、决策与就绪门

## 事实标签
CONFIRMED（已核实）/ INFERRED（推断）/ ASSUMPTION（假设，需写回退条件）/ UNKNOWN / NOT_FOUND / N/A（写理由）/ BLOCKED。

## 证据链（替代“三级凭据”）
- E1 来源：需求编号、决策编号、任务卡验收条款。
- E2 实现：文件路径 + 符号/行号 + 提交号。
- E3 验证：实际命令 + 退出码 + 关键输出/证据文件；性能类要有基线、同环境对照和改动后实测。
- E4 独立复核：测试助手或第二模型核对（高风险任务才要求）。
同一来源被多份文档转抄不算多层证据。纯规划阶段 E3 可以是 NOT_YET_VERIFIED。

## 决策记录
字段：id（全项目唯一，跨版本不复用）、title、status（PROPOSED/OPEN/DECIDED/SUPERSEDED/REJECTED）、decided_by（user/planner）、decided_at、file、applies_to（任务 ID）、supersedes/superseded_by、reopen_conditions。
- 旧项目里各版本各自的编号（如 Q-11-01、U-23）在 BOOTSTRAP 时登记为 `legacy_ids`，统一进一个登记册。
- 推翻用新决策 + superseded_by，不改旧文件结论。

## 完整度矩阵（按相关性选项，不相关写 N/A+理由）
需求与验收 / 前端与交互 / 后端与接口 / 数据与迁移 / 架构与复用 / 性能与资源 / 安全与配置 / 知识库与内容 / 测试与发布。
每项状态：已确认 / 待澄清 / 待验证 / N/A / BLOCKED。用“12 项中 9 项有证据、2 项待验证、1 项阻塞”表达完整度，不报主观百分比。

## 就绪门判定
- READY：需求和验收明确，依赖满足，无会改变方向的未决问题。
- CONDITIONAL：有已登记的非阻塞假设（含适用范围、回退条件）。
- BLOCKED：重大决策未定、契约不明、需求冲突、无法验收 → 改代码前上报，只暂停受影响任务。
能通过读代码/跑命令查明的，先查，不交给用户。

## 讨论完成条件
1. 目标用户、核心问题、范围、非目标清楚。2. 每条 MUST 有可验证验收或标为待澄清。3. 相关领域已过矩阵。4. 重要方案做过正反论证。5. 已确认决策全部落盘。6. 未知项有状态和后续处理。7. 没有会推翻方案的未决问题。8. 继续讨论预计不会改变任务结构。
